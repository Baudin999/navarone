# SplitComplexity

Check id: `split-complexity`. Subject: method. Default limit: 10. A finding is raised only above the limit.

The trick an agent reaches for: split a method into helpers so each piece passes while the whole does not. Each method scores lower, while every decision is still there. Nothing got simpler; it moved.

It is measured on the code as it is now, with no git history. A helper is any method of the method's own type or of a type nested in it, at any depth and whatever its accessibility, whose callers are all the method or other helpers. Making a helper `internal` or moving it into a private nested class does not hide it. A call into any other type, the type the method's own type is nested in included, is a hand-off to a different job, not a split: without this a pipeline entry such as `Main` owns every method below it. A method that implements an interface member or overrides a base member declared outside the method's own type and the types nested in it, `MethodFacts.Contracts`, is no helper: it is called through that contract, such as `ISignal.Id`, so the one caller the provider resolves is not all its callers. A private interface declared inside the type to wrap helpers in a contract hides nothing: they stay helpers. Each helper and the method itself are at or under the cyclomatic limit; a piece over it is already red for cyclomatic.

The value is the method's decisions plus each helper's decisions, cyclomatic minus one, plus one: the cyclomatic the method would have with its helpers inlined. Inlining a split scores the same as the split, and a helper without decisions adds nothing, so the check measures the split, not the number of methods. Every helper adds its decisions, a flat dispatch or a mapping included: exempting them would let an agent hide any number of decisions in helpers shaped like one. A method raises the finding when that value is over this check's limit.

The finding carries its helpers, `Finding.Helpers`, each with its method name and the decisions it adds, from the same computation that gives the value. Its question ends with the ledger of the helpers that add a decision, `Left(int) adds 2`, and the deterministic reason classifier rejects a reason for the split that does not name each of them. A helper's method name is the first word of its short name: `Parse` for `Parse(string)`, `Total` for `Total.get`.

No rule calls a split a false positive, since a split is often ordinary decomposition, such as a parser with one reader per state, and the agent answers it with a reason. It reads the cyclomatic results of the method and its helpers through `CyclomaticMetric.ValueOf`, so the two checks count one number the same way. It reads `TypeFacts.ContainingType` to find the types nested in the method's type, each method's `Calls` across the whole codebase to find the helpers called only from the method, and the cyclomatic limit and its own limit from `CheckLimits`.
