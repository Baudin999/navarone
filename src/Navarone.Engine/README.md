# Navarone.Engine

The language agnostic core. It runs the checks over the facts a provider hands over, grants ids to new problems, classifies them, stores the agent's reasons as resolutions, owns `reasons.json` and reports the verdicts.

- `Analysis.cs`: the entry points. `RunAsync`, behind `navarone`, loads each codebase on its own and merges their facts, so a subject two codebases share is one subject. It runs every check, matches each finding against `reasons.json`, grants an id to each new problem, asks the problem classifier about every problem on every run, removes the problems whose code is gone, and returns one verdict per problem its coverage shows. `ResolveAsync`, behind `navarone <id> "<reason>"`, checks the repo the same way, asks the reason classifier about the reason, and stores a reason no rule rejects as the problem's resolution, logged with the code it defends; a reason for a fixed problem whose fix the validator refused is logged and stored nowhere. `KeepAsync` and `ReplaceAsync`, behind `navarone <id> keep` and `navarone <id> replace <rule> "<finding>"`, find how the builder answered a problem, a reason that turns it green now or the last fix logged on the worktree, and log the validator's position, reading the code without writing `reasons.json`; a replace's rule is the rule with its number in the NAVARONE.md at the repo root when it has one, otherwise the setup's, read through `Clashes/TasteRules`. `LargeChangeAsync`, behind `navarone <id> large "<text>"`, stores the text as the problem's resolution and logs the large change with the subject's code, and `SettleAsync`, behind `navarone <id> settled`, logs the user's decision on it and adds a keep's words to the resolution. `RunAsync` collects the user's judgements of clashes and holds each problem in a clash red through `Clashes/`. Each entry point logs the events it makes happen; `RunAsync` returns them in a `CheckRun` with its verdicts, and `LogRun` writes them with the run once the CLI knows what printing cost. `FindingOfAsync` is the finding of one problem in the code as it is now, read-only, behind `navarone evidence <id> --json`.
- `CheckedRepo.cs`: the repo as a command checks it: every problem a check found in the code as it is now, matched against `reasons.json`, with each subject's code, ids and places. It owns `reasons.json`: a command saves it only through `CheckedRepo`, so no save brings a gone problem back.
- `RunEvents.cs`: what a `navarone` run made happen on its worktree, beside the ids it granted and the answers it collected: a fixed for each open problem the builder fixed, a raised for each shown red problem that is not open, and the run's entry for each problem it shows.
- `BuilderAnswer.cs`: the builder's answer to a problem, a fix or a reason, which the validator's keep or replace answers, and the refusal a replace logs.
- `Lenses/`: the lens behind `navarone lens`, a small language with its own lexer, parser and execution. `LensLexer` and `LensParser` read a lens's text by its grammar, `Lens` holds the subject and its views, `MethodLensRules` and `LensViewRule` say which views a method takes and the parameters of each, and `MethodLens` shows them from the facts as one `LensPage` of sections, blocks and marks: callers, expand and class. The page writes itself as markdown, through `Markdown`, and as JSON for brain's window, from the blocks in `LensBlocks`. `LensQueries` names a method in a lens, chooses the overloads a lens's name picks, and builds the lens that makes a method the subject, for a mark on a call. `LensVersion` names the version of the code a lens shows, from `Git`, which reads HEAD and the status. It reads facts only and writes nothing.
- `Clashes/`: a clash between the builder and the validator, which the user judges in brain's window. It collects his judgements from brain's answers, says which problems a clash holds red, builds the questions `navarone disputes --json` lists, and reads the rules of NAVARONE.md a refusal names.
- `Events/`: Navarone's event log and code store. `NavaroneEventHandler` alone writes the log and reads it back. Every event type implements `INavaroneEvent`, and `WorktreeHistory` reads what the log says of each problem on one worktree.
- `Coverage.cs`: which problems `RunAsync` returns: every one, for `navarone --full-coverage`, or those whose code the change since the default branch touches, for `navarone`. A problem is shown when a changed line falls in its method, in its class's first declaration or any field or method of its class, in whichever partial declaration it is written, or in a helper of its split. `LineRange` is the lines a change touches in one file.
- `Code.cs`: the code a command reads, the provider, the repo root and the codebases, whose `FactsAsync` loads each codebase and merges their facts. Every command that reads the code goes through it: the entry points of `Analysis`, the lens and the clone detector.
- `Cache/`: the facts cache in `.navarone/` at the repo root, which `Code.FactsAsync` reads before it loads every codebase and writes after, keyed by the version of the code. It keeps only complete facts.
- `AtomicFile.cs`: writes a file whole or not at all, through a temp file moved over the target. reasons.json, navarone.json, the code store and the facts cache write through it.
- `Git.cs`: the git checkout of the repo, read only. It reads HEAD and the status for the lens, the branch and the main checkout for an event's place, and the commit where HEAD left the default branch and the lines changed since, for the coverage.
- `Duplication/`: the clone detector behind `navarone duplicates`, research toward a duplication check. It finds duplicated code in the normalised tokens of every method and reports each clone pair at or above a floor. It reads facts only and writes nothing.
- `EngineSetup.cs`: what the engine runs with: the provider, the checks, their limits, the problem and reason classifiers, the repo root that holds `reasons.json`, the event log, and brain's answers.
- `Providers/`: the provider contract.
- `Facts/`: what a provider hands over.
- `Metrics/`: the check contract.
- `Configuration/`: `navarone.json`, with each check's limit and what the repo ignores.
- `Findings/`: what a check hands back, the kind of subject it names, and the evidence of how a check came to its value.
- `Classification/`: the contracts for classifying a problem and a reason.
- `Reasons/`: `reasons.json`, the ids Navarone grants, each problem's resolution, the fingerprint that opens a problem again when its code changes, and the verdict of each problem.

This project references no other Navarone project and no parser. No Roslyn type and no language name appears here. Once the engine learns a language, every other language has to pass through it.
