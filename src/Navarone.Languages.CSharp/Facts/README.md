# Facts

`FactExtractor`: walks every C# document of a loaded solution and maps it onto the engine's facts, through `TypeBuilder`, which gathers a type with its fields, `TestClass`, which says whether a type is a test class, `MethodReader`, which reads the methods a member declares, `PropertyReader`, which ties a property or indexer with a body to its accessors, so the class view shows it as one member, and `InitializerReader`, which reads the initializers that hold logic. `BodyFacts` is what the bodies of either hold, and `SourcePlaces` where code is written. It reads no project whose name a project glob of `navarone.json` matches and no file a file glob matches, and leaves a field declared in an ignored file out of its type. A method is any method, constructor, destructor, operator or accessor with a body, an expression-bodied property or indexer, and the top-level statements of a program. A method declared without a body, abstract, extern or partial, is a method too, with no control flow and no uses, until a declaration of it with a body is read; a `[GeneratedRegex]` method's body is the source generator's and never is. A primary constructor is a constructor without a body whose field uses are what it sets: a record's parameter sets the property of its name, a class's or struct's parameter is a field of its own. A lambda or a local function is part of the method it is written in. A field, property or event initializer that holds logic, a lambda or anything that breaks the straight line, is a method too, under its member's symbol and named by its member's name, and it uses its member as a field when another method of the type reads that member, so a body moved into `static readonly Func<...> X = ...` is measured all the same. A file two projects compile, such as a project built for two target frameworks, is read once. Only what the build generates is skipped: anything under `obj/`. A source generator's files are not among a project's documents. A file named `.g.cs` or `.designer.cs`, or one that opens with `<auto-generated/>`, is measured, since anyone can write either.

`ControlFlowReader` maps the constructs that break the straight line onto the engine's `ControlFlowKind`. Each fact names its construct as C# writes it, such as `if`, `else if`, `case`, `arm`, `when`, `subpattern`, `default`, `_`, `var`, `&&`, `?:` or `do while`, and spans its head in the file: an if's keyword and condition without its body, from the `if` for an else if, a loop's head, the `do` alone for a do while, a case's label, an arm's pattern and guard, a subpattern whole, and an operator with both its sides. A subpattern is a `PatternTest` when it tests a value, such as `IsConst: false` or `ContainingSymbol: IMethodSymbol c`; one whose pattern is `var n` or `_` tests nothing and is no fact. A case or arm whose pattern is a discard or a var pattern, `_ when c`, `var x` or `case var _:`, tests nothing either and is a `Default`; its when is a `Guard` of its own. A list pattern is a `PatternTest`, `list`, for its length unless a lone slice such as `[..]` takes any length, and each element that tests a value is a `PatternTest`, `element`, a part of its list; the element of a slice is the slice's pattern, a discard or var element is none, and an element counts whatever it holds, while what it holds counts on its own, so `[[1]]` is a list, an element, the inner list and its element. An element such as `'a' or 'b'` or `[1]` is two facts on one node, the element and the `or` or the list as its part. A `not` in a pattern is no fact: like a `!`, it flips a test that is already counted. A fact is part of the nearest construct around it, so the `&&` and `||` in an if's condition are parts of the if, a when clause and a subpattern are parts of their case or arm, and a case part of its switch. A statement is part of nothing, and a statement between two constructs ends the search, so an if inside a loop's body is no part of the loop. `ParameterSteering` decides which parameters steer a branch, as the control-coupling README states. `FlatDispatch` decides whether a method body is a flat dispatch: one switch statement or switch expression, a chain of else ifs, or a chain of conditional expressions whose every else is the next condition, `k == A ? "a" : k == B ? "b" : "c"`, whose every branch is one return, throw or expression with no control flow of its own, braces aside. A switch section may be one expression and a break, or a break alone. A test, the governing expression, a condition, a case label or a pattern, is one test: an `&&`, an `||`, a property or positional pattern, a list pattern that tests a length or an element, a lambda, a loop, an if, a `?:`, a switch or a catch in a test makes the method not flat, and so does a case or arm with a when. A pattern may join constants or types with `or` and `and`, such as `'b' or 'c'`, which only names the cases of one branch. A run of ifs counts as a chain when every branch returns or throws, and one return or throw may follow the dispatch. A flat dispatch is a mapping when it returns a value, no branch is an expression statement or a `return;`, and nothing outside a throw is an invocation, an assignment, an increment, a decrement or an `await`; an object creation is a value. `TypeBuilder` gathers a partial class from every file it is declared in, with its fields.

`CodeTokens` reads a method's tokens from its bodies, the same bodies its control flow comes from, a constructor's initializer included. Every identifier has the shape `id`, a contextual keyword such as `var` included, since C# lexes it as an identifier. Every literal has the shape `lit`: a number, a character, a string, an interpolated string's text, a raw string, `true` and `false`. `null` and every other keyword or punctuation keep their text. Comments, whitespace and directives are trivia, never tokens.

`Symbols` names each symbol as its assembly, its containing type in full, and its own name with its parameter types by name only: `Compiler::Compiler.Parser.Parse(Token, string)`. The assembly keeps two programs' `Program` apart. A parameter type is named without its namespace, so the symbol reads the same whether or not the package that declares the type was restored; with the namespace, a restore would rename the method and lose its id. A symbol is named once and its name kept while its compilation lives, since every call site names its callee.

`SymbolUses` reads each call and field use from the operations the compiler binds a body to, so every use counts whatever syntax writes it: a call, an object creation, a method group, an operator, a user-defined conversion, an indexer, a foreach's `GetEnumerator`, `MoveNext`, `Current` and `Dispose`, a collection initializer's `Add` and a `Deconstruct`, in a deconstruction, a foreach or a positional pattern. Each use becomes its symbol's `SymbolId`, on the line of the name that writes it, in the order written. A `nameof` uses nothing: it names a symbol and calls none. A call into the framework is a call like any other: an accessor that makes one does work, so its class is no value class. Each method and type also carries its declaration as written, name included and leading comments left out, as `Code`, so the engine can fingerprint it. An accessor's `Code` starts with its property's signature, so a change to the property's type voids it too. Writing the `// navarone: <id>` comment does not change the fingerprint. A class's `Code` leaves out the navarone comments written anywhere in it, and its ids are those written anywhere in it.

A use of a property with a body, an indexer's included, is a call of its accessor: an assignment or a deconstruction into it calls the setter, `+=`, `??=` and `++` both, anything else the getter. The `field` keyword in an accessor uses its property as a field, as a use of an auto-property does.

A parameter of a class's or struct's primary constructor is a field of the type, and a member that reads it captures it, so the read is a field use. A read in an initializer copies the value once and is not. A record's parameters become properties, which are fields already.

`?.`, `??` and `??=` are each a `NullCheck`. A flat dispatch may hold them.

A property's or indexer's getter or setter is an accessor, `IsAccessor`; an event's add or remove is not. A member declared private, by its modifier or by default, is `IsPrivate`. A method's `Contracts` are the types that declare what it overrides, up the chain, and the interfaces whose members it implements, explicitly or not, an accessor's included. A nested type names the type it is declared in as its `ContainingType`.

It also reads the `// navarone: <id>` comments in the leading trivia of a method, a class, an initialized field, or the property of an accessor into that declaration's `NavaroneIds`. A comment between the attributes and the signature counts too, and stays out of the fingerprint:

    // navarone: 0001234
    public decimal Calculate(Order order) { ... }

    [HttpGet]
    // navarone: 0001235
    public IActionResult Get() { ... }

The provider passes each id on as written. Whether it matches its problem is the engine's to decide.

Metrics do not live here. This folder decides what the C# code is, never what the numbers are.
