# Subjects

- thesis: Why Navarone exists: fighting slop so every change leaves the code better.
- slop: How code goes stale under agents: drift, duplication, a foundation chipped change by change.
- discipline: What the builder must not skip: understand, apply patterns, remove, test what matters, tell a story.
- process: How a change flows through Navarone: signal, builder, validator, user.
- agents: The builder and the validator: who looks, who reviews, who lands.
- signal: A static analyzer's finding: a reason to look, never a verdict or a solution.
- complexity: Decisions and flow inside one method: cyclomatic, cognitive, split complexity.
- cohesion: Whether a class holds one job: LCOM4.
- coupling: How code steers other code: control coupling, flag parameters.
- duplication: Copied blocks, repeating blocks, the same idea built twice.
- taste: The user's taste in code: what makes it beautiful and easy to change, and how agents get it.
- review: The validator's review and the clash that reaches the user.
- resolution: A decision tied to a piece of code: ids, reasons, decided stays decided until the code changes.
- exclusion: What Navarone does not check: ignored files and projects.
- lens: Navarone's static view into the code: the context a method needs to be judged.
- settling: Brain's window where the user settles what reaches him: positions, disputes.
- architecture: Navarone's own parts: engine, language providers, checks.
- csharp: C# through Roslyn: the one language provider so far.
