# Navarone fights slop: every change leaves the code in better shape than it was, through discipline with the user's taste at the root

We are fighting slop. A project gets stale when it is built with agents: change upon change lands, and each one chips away at the foundations of what the project does. Each change looks fine on its own; together they drift away from how the user would have built it. The same idea gets built twice in two shapes, a method gets crammed where it should tell a story, and a missing design gets patched over in the leaves.

Brain is the answer for information. Navarone is the answer for the code. For that, code has to be written so that every change makes it better, and leaves the system in better shape than it was. That takes discipline, and Navarone is the tool that enforces it, with the user's taste at the root.

Discipline means not skipping steps:

- Understand what needs to be built.
- Look for patterns and apply them.
- Do not duplicate code.
- Security and performance are always at the root of what we create.
- Remove as much as you can without breaking functionality. Never fear the delete: removing makes things simpler.
- Ask questions when you are unsure, about functionality, not about procedure.
- Write tests that matter: not because you have to, but because functionality must be preserved.
- Tell a story. The agent's code is dense; the user's code tells a story.
- Do not fear the refactor. When a pattern is wrong and leads to bad code smells, fix it. When the fix is a big change, bring it to the user.

## Why
Agents land change upon change, and each one chips away at the foundations of what the project does, so a project goes stale. Brain is the answer for information, Navarone is the answer for the code.
