# Every position on a clash Navarone puts before the user is keep or replace: the builder's, the validator's and the user's

On every item Navarone puts before the user, each side's position is classed as keep or replace. The builder is keep when it recorded a resolution, because it defends the code as it is, and replace when it fixed. The validator is keep when it accepts the code as it is and replace when it sends a finding back. The user answers Keep or Replace. The window shows the positions visually, so agreement and disagreement read at a glance, and each resolution in the history carries its positions too, so the user sees where they flipped. The class comes straight from the stored positions, with no model. Each item also opens with one plain sentence that says what the user judges.

## Why
Looking at real items, the user could not tell what judgement was asked of him, or whether the agents agreed. His words: "I do not really understand 'what judgement is asked of me'." Keep or replace is the one question underneath every item: should this code stay as it is or change.
